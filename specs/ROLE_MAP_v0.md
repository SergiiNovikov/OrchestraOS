# ROLE_MAP_v0.md

---

## 1. Статус Role Map

**Role Map v0** — минимальная, согласованная и архитектурно зафиксированная карта ролей системы оркестрации, следующих строго после Front Manager.

Role Map v0 фиксирует базовый, обязательный набор ролей и их границы ответственности для MVP системы оркестрации. Документ служит архитектурным контрактом и базовой точкой для дальнейшего расширения Role Map в версиях v1+ в соответствии с дорожной картой проекта «Разработка».

---

## 2. Инварианты Role Map

- Front Manager не входит в Role Map и не описывается в данном документе.
- Все роли считаются stateless, если явно не указано иное.
- Каждая роль обязана работать по схеме:  
  **один входной артефакт → обработка → один выходной артефакт → завершение**.
- Роли не смешиваются и не дублируют ответственность.
- Ни одна роль не выполняет функции, закреплённые за другой ролью.
- Role Map v0 не включает:
  - реализацию;
  - код;
  - выбор технологий или LLM;
  - UI или UX;
  - автоматизацию процессов.

## 4. Описание ролей

### 4.1 Scope Resolver

**Назначение:**  
Определение типа запроса и допустимого контура его обработки.

**Входной артефакт:**  
- Request Envelope

**Выходной артефакт:**  
- Scoped Request

**Зона ответственности:**  
- классификация запроса по типу;
- определение допустимого набора последующих ролей;
- ограничение области дальнейшей интерпретации.

**Предотвращает:**  
- дрейф класса задачи;
- запуск неподходящих контуров обработки;
- смешение reasoning- и execution-контуров.

**Запрещённые действия:**  
- интерпретация пользовательского намерения;
- декомпозиция задач;
- выполнение задач;
- модификация Request Envelope.

---

### 4.2 Intent Interpreter

**Назначение:**  
Извлечение и формализация явного намерения пользователя.

**Входной артефакт:**  
- Scoped Request

**Выходной артефакт:**  
- Interpreted Intent

**Зона ответственности:**  
- перевод пользовательского запроса в системно определённое намерение;
- устранение смысловой двусмысленности;
- фиксация цели запроса.

**Предотвращает:**  
- галлюцинации цели;
- подмену задачи интерпретацией модели;
- генерацию ответов, не соответствующих намерению пользователя.

**Запрещённые действия:**  
- декомпозиция задач;
- планирование исполнения;
- выполнение задач;
- оптимизация формулировки намерения.

---

### 4.3 Task Decomposer

**Назначение:**  
Декомпозиция намерения на минимально необходимые задачи.

**Входной артефакт:**  
- Interpreted Intent

**Выходной артефакт:**  
- Task Graph

**Зона ответственности:**  
- разбиение намерения на задачи;
- фиксация последовательности и зависимостей;
- формирование детерминированной структуры задач.

**Предотвращает:**  
- пропуск логических шагов;
- неявные рассуждения;
- «магическое» выполнение без явных задач.

**Запрещённые действия:**  
- назначение ролей;
- выполнение задач;
- оптимизация или упрощение Task Graph;
- изменение намерения.

---

### 4.4 Role Orchestrator

**Назначение:**  
Назначение ролей-исполнителей для каждой задачи.

**Входной артефакт:**  
- Task Graph

**Выходной артефакт:**  
- Execution Plan

**Зона ответственности:**  
- сопоставление задач ролям;
- обеспечение одного исполнителя на одну задачу;
- фиксация порядка исполнения.

**Предотвращает:**  
- дублирование выполнения задач;
- конкуренцию ролей;
- скрытое или неявное выполнение.

**Запрещённые действия:**  
- декомпозиция задач;
- выполнение задач;
- изменение Task Graph;
- интерпретация пользовательского намерения.

---

### 4.5 Execution Roles (класс ролей)

**Назначение:**  
Выполнение конкретных задач согласно Execution Plan.

**Входной артефакт:**  
- Task Instruction

**Выходной артефакт:**  
- Task Result

**Зона ответственности:**  
- строгое выполнение назначенной задачи;
- следование полученной инструкции без отклонений.

**Предотвращает:**  
- выход за рамки задачи;
- самовольное перепланирование;
- контекстный дрейф.

**Запрещённые действия:**  
- изменение Execution Plan;
- интерпретация намерения пользователя;
- координация с другими ролями;
- агрегация результатов.

---

### 4.6 Result Assembler

**Назначение:**  
Сбор результатов выполнения в финальный артефакт ответа.

**Входной артефакт:**  
- Set of Task Results

**Выходной артефакт:**  
- Final Response Artifact

**Зона ответственности:**  
- агрегация результатов задач;
- проверка полноты выполнения Execution Plan;
- структурирование финального ответа.

**Предотвращает:**  
- потерю частей результата;
- добавление нового смысла;
- рассинхрон между задачами и ответом.

**Запрещённые действия:**  
- выполнение задач;
- изменение Task Results;
- интерпретация пользовательского намерения;
- оптимизация или расширение ответа.

---

## 5. Артефакты и границы передачи

### Перечень артефактов

- Request Envelope — производит Front Manager
- Scoped Request — производит Scope Resolver
- Interpreted Intent — производит Intent Interpreter
- Task Graph — производит Task Decomposer
- Execution Plan — производит Role Orchestrator
- Task Instruction — производит Role Orchestrator
- Task Result — производят Execution Roles
- Final Response Artifact — производит Result Assembler

### Границы доступа

- Каждая роль имеет право читать только входной артефакт.
- Модификация входных артефактов запрещена.
- Передача данных осуществляется только через явные артефакты.
- Неявная модификация или обогащение артефактов запрещены.

---

## 6. Минимальный состав для MVP

**Обязательные роли:**
1. Scope Resolver  
2. Intent Interpreter  
3. Task Decomposer  
4. Role Orchestrator  
5. Execution Roles (обобщённый класс)  
6. Result Assembler  

**Обоснование:**  
Данный состав является минимально достаточным для обеспечения линейного, проверяемого и недублирующего pipeline обработки запросов после Front Manager.

---

## 7. Явно исключённые зоны

Role Map v0 не покрывает:
- реализацию ролей;
- выбор технологий или моделей;
- оптимизацию pipeline;
- автоматизацию;
- UI и UX;
- мониторинг, логирование и метрики.

Все перечисленные зоны намеренно отложены на последующие версии Role Map.

---

## 8. Статус завершённости

Role Map v0 считается архитектурно завершённой и зафиксированной.

- Любые изменения требуют повышения версии (v1+).
- Неявные изменения карты ролей запрещены.
- Role Map v0 используется как неизменяемый архитектурный контракт для разработки и валидации системы оркестрации.
